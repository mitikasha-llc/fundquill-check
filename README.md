# fundquill-check

**An engine-free, offline verifier for [FundQuill](https://fundquill.com) signed reports, audit
trails and assumption libraries.**

FundQuill audits Excel financial models in the browser and can export a signed report of what it
found. `fundquill-check` lets anyone who receives such a document confirm, on their own machine:

- that it is **unaltered** since it was produced,
- **which device key signed it**, and
- optionally, that it describes **their own copy of the model**.

It uses public algorithms only (SHA-256, ECDSA P-256). No FundQuill engine runs and nothing is
uploaded.

## Why trust this (and not have to)

- **Public source, no dependencies.** About 270 lines across `src/canonical.js` and `src/verify.js`.
  The full document format is written out at the top of `src/verify.js`.
- **Offline.** It makes no network requests. Run it air-gapped.
- **Hash-pinned.** Each release records the SHA-256 of its artifacts in [MANIFEST.md](MANIFEST.md).
- **Independent of fundquill.com.** FundQuill's in-app checker (fundquill.com/verify) and this
  package are tested against the same fixture files and the same expected verdicts, so they agree,
  but you only need this one.

## Use it

### Terminal / CI

```sh
npx fundquill-check model.fundquill-report.json model.xlsx --fingerprint <hex from the sender>
```

| Option | |
|---|---|
| `[model.xlsx]` | Your copy of the model. Its SHA-256 must match the one the document records. |
| `--fingerprint <hex>` | Require this signing-device fingerprint. |
| `--allow-unsigned` | Pass an intact but unsigned document (FundQuill Free reports are unsigned). |
| `--json` | Machine-readable output. |

Exit codes: **`0`** verified, **`1`** not verified, **`2`** usage or I/O error.

### Browser (zero install)

Build the self-contained single file with `npm run build:html` and open `dist/check.html`, or
download it from a GitHub release. It works from disk with no network.

### Library

```js
import { verify } from 'fundquill-check';
const result = await verify(JSON.parse(text), { model: bytes, expectFingerprint: fp });
// result.ok, result.hashOk, result.signatureOk, result.signerFp, result.checks
```

## What it checks

| Check | Proves |
|---|---|
| **Hash chain** | Every chained section recomputes to the recorded root, so nothing in them changed. A failure names the changed sections. |
| **Header** (spec version 2) | The top-level `tool` / `kind` / `spec_version` and the `reproduce` line agree with the chained `build` section. |
| **Signature** | The device key embedded in the document signed the root. The device fingerprint is computed from that key, never taken from the document. |
| **Expected signer** | With `--fingerprint`: it was that device. |
| **Model** | With a model file: its SHA-256 is the one the document records. |

It also reports the engine build (version and the SHA-256 of the engine that ran) and flags Monte
Carlo outputs where trials errored.

### What it does not prove

- **A key is not a person.** A valid signature shows which device key signed. Get the expected
  fingerprint from the sender through a channel you already trust.
- **It does not re-run the engine.** The numbers are as produced. The document records exactly which
  engine build produced them.
- **Version 1 documents** (issued before October 28, 2026) do not cover their engine version or
  generation date; the checker says so rather than presenting them as verified.
- Fields outside the hash chain (such as a Free-tier `watermark`) are never reported.

## Document versions

- **spec version 2**: the chain opens with a `build` section (tool, kind, spec version, engine
  version, engine SHA-256, generated at). Everything the document asserts is signed.
- **spec version 1**: the original format. The content sections are signed; the engine version,
  date and `reproduce` line are not.

## Develop

```sh
npm test             # node --test, no dependencies
npm run build:html   # dist/check.html (offline single file)
```

`test/fixtures` is generated by FundQuill's own code (`apps/web/src/lib/fixtures` in the FundQuill
repository), with an `expected.json` verdict per file.
